2. **포지셔닝은 "20년 경력에, 지금도 매주 이민법 소식을 직접 전하는 변호사"로 잡는다.**
   참고 사이트 4곳 중 3곳은 소식·칼럼이 몇 년째 멈췄거나(2020년, 2024년) 글에 날짜조차 없다. 최신성과 꾸준함이 가장 확실한 차별점이다.

   업무분야 4개는 각각 구조화된 고정 페이지로 만든다. 글을 쓸 때 업무분야만 체크하면 해당 페이지에 '관련 글'로 자동으로 쌓이므로, 따로 손대지 않아도 페이지가 계속 풍부해진다.

   제작사가 월정액으로 계속 관리하는 것을 전제로 영상 히어로, 슬라이더, 스크롤 애니메이션, 비자 진단 퀴즈 같은 화려한 구성을 쓴다. WordPress이므로 의뢰인 질문 2(업체를 바꾸면 옮길 수 있나)에는 여전히 "옮길 수 있다"고 답할 수 있다. 대신 두 가지는 지킨다. 게시글은 기본 블록 에디터로 써서 핵심 자산을 빌더와 분리하고, 속도 예산을 운영해 검색 성과를 지킨다(§9).
6. **도메인, 각종 계정, 콘텐츠는 처음부터 의뢰인 명의로 둔다.**
   제작사는 관리 권한만 갖는다. 해지할 때 전체 백업과 이전 지원을 제공한다는 내용을 계약서에 적는다. 이것이 신뢰를 얻고 수주 가능성을 높인다.
7. **"구글 1면 노출"은 보장할 수 없다고 솔직하게 답한다.** 대신 어떤 SEO 작업이 포함되는지, 현실적인 일정과 측정 지표는 무엇인지 함께 제시한다.
8. **`hkimlaw.com`은 이미 다른 사람이 등록했다(2026-09-16).**
   지금 비어 있는 `vincentkimlaw.com`이나 `vinkimlaw.com`을 의뢰인 명의로 바로 등록하도록 권한다.
9. **법규 리스크를 먼저 챙긴다.** 대상은 캘리포니아 변호사 광고 규정(Rule 7.1·7.2·7.4), 개인정보처리방침 의무(CalOPPA), 웹 접근성(ADA·Unruh)이다. 이런 점을 먼저 챙기는 업체라는 인상 자체가 경쟁력이 된다.

### 2.2 메일 행간에서 읽히는 요구사항

- **"늘 계획하는 것만으로 끝나는게 문제" → 운영을 지속하지 못하는 것이 가장 큰 리스크다.** 기능보다 쓰기 쉬움과 루틴이 먼저다. 채널은 단계적으로 늘린다.
- **"제가 모르는게 너무 많습니다" → 믿을 수 있는 조언자를 기대한다.** 견적 금액보다 투명한 설명이 수주를 결정한다.
- **"마음에 딱 드는 사이트는 없다" → 참고 사이트를 그대로 베낀 시안은 실패한다.** 각 사이트의 장점을 조합하되 더 현대적이고 더 최신이어야 한다.
- **소규모 사무실이다 → 상담 문의 처리 흐름이 단순해야 한다.** 이메일, 카카오톡, 전화면 충분하다.
- **카페 게시판을 많이 쓴다 → 날짜와 제목 중심의 목록이 익숙하다.** 방문자용 화면은 그보다 읽기 좋게 만든다.
- **잠재 고객이 한국과 미국 양쪽에 있다 →** 한국 거주자는 네이버로, 미국 거주자는 구글로 찾아온다. 둘 다 대응해야 한다.

2. **콘텐츠 정체와 날짜 미표시**(3곳) → 작성일과 최종 업데이트일을 전면에 보여 주고, 꾸준함 자체를 마케팅한다.
3. **무관한 스톡 사진과 의미 없는 슬라이더** → 실제 인물, 실제 사무실, 실제 방송 사진만 쓴다. 영상과 슬라이더는 쓰되 장면마다 분명한 메시지를 담는다(§13.1).
4. **목록을 탐색하기 어려움**(분류·검색 없음) → 업무분야와 글 유형으로 필터링하고 사이트 내 검색을 제공한다.
5. **공유 기능 없음** → 카카오톡, Threads, Facebook 공유와 자동 공유 이미지를 제공한다.
6. **비자 이름을 알아야만 찾을 수 있음** → "어떤 상황이신가요?" 같은 상황별 진입로를 만든다.
7. **영어 처리 미흡** → 영문 핵심 페이지를 D·E 페르소나에 맞춰 설계한다.
8. **근거 없는 수치와 "높은 성공률"** → 검증 가능한 사실로만 신뢰를 쌓는다. 20년 경력, 글 1,500편 이상, 카페 회원 2,100명 이상, 방송 출연이 그 예다.

## 4. 전략 방향

### 4.1 포지셔닝

- **한 줄 정의:** "20년 경력에, 지금도 매주 이민법 소식을 직접 전하는 변호사"
- **근거(검증 가능한 사실만 사용):** 이민법 20년 / 네이버 블로그 글 1,500편 이상 / 2015년부터 운영한 카페의 회원 2,100명 이상 / KBS America 등 방송 출연 / 다수의 승인 사례. 이 수치를 홈페이지에 쓸 수 있는지 [확인 필요].
- **쓰지 않을 표현:** "최고", "100% 승인", "높은 성공률"처럼 검증할 수 없거나 결과를 보장하는 표현(§12).

### 4.2 카피 후보 (시안용, 최종 문구는 의뢰인 승인과 광고 규정 검토 후 확정)

- **한국어 헤드라인**
  - "20년, 이민의 길을 함께 걸어온 변호사"
  - "가장 빠른 이민법 소식, 20년의 신뢰"
  - "복잡한 이민법, 끝까지 직접 챙기겠습니다"
- **서브 카피:** "영주권·비자·시민권·추방재판, 김형걸(Vincent Kim) 변호사가 직접 상담합니다."
- **영어:** "Twenty Years of Guiding Immigrants in Los Angeles" / "Immigration counsel in Korean and English."

### 4.3 채널 전략: 허브와 스포크

```
        [인지]  YouTube Shorts · Instagram · Threads · Facebook
                       │  짧은 요약 + 링크(UTM)
                       ▼
 [관계] 네이버 카페(Q&A) · 오픈카톡 ──새 글 알림 + 링크──▶ ┌──────────────────────────────┐
                                                          │  홈페이지 = 허브(원본, 내 소유)  │
 [검색] 구글 검색 · Google 지도(GBP) · 네이버 검색 ────────▶ │  이민법 소식 / 전문가 칼럼      │
                                                          │  업무분야 / 변호사 소개         │
                                                          └──────────────┬───────────────┘
                                                                         │ 전환
                                                                         ▼
                                                        상담 신청 · 전화 · 카카오톡
```

| 채널 | 역할 | 형식 | 목표 빈도 | 도입 시점 |
|---|---|---|---|---|
| 홈페이지 | 원본 저장소, 검색 유입, 상담 전환 | 상세 글 | 주 2개 | 오픈 |
| 네이버 카페 | Q&A 커뮤니티 유지 | 요약과 "전문 보기" 링크, Q&A 답변 | 주 2개 | 오픈 |
| 네이버 블로그 | 네이버 검색 유입 | 요약 또는 재구성한 글과 링크 | 주 1~2개 | 오픈 |
| 오픈카톡 | 알림 | 제목과 링크 | 새 글마다 | 오픈 |
| Google 비즈니스 프로필 | 지도·지역 검색 | 소식 게시물, 사진, 리뷰 | 주 1회 | 오픈 |
| Facebook 페이지 | 40~60대 한인에게 도달 | 요약과 링크(자동 공유) | 새 글마다 | 2단계(+1개월) |
| Threads | 짧은 대화형 글 | 500자 요약과 링크(자동 공유) | 새 글마다 | 2단계 |
| Instagram | 시각적 인지 | 카드뉴스 5~7장 | 주 1회 | 3단계(+3개월) |
| YouTube Shorts | 발견과 신뢰(얼굴 노출) | 30~60초 세로 영상 | 월 4편(한 번에 몰아 촬영) | 3단계 |

> **단계적으로 도입하는 이유:** 의뢰인 스스로 "계획만 하고 끝난다"고 했다. 채널을 처음부터 7개로 벌리면 모두 멈춘다. 1단계(홈페이지와 네이버·카톡·지도)가 습관이 된 뒤에 늘린다.

**네이버와 중복 게시하는 원칙:** 홈페이지에 원문을 **먼저** 발행한다(구글이 원본으로 인식하게). 네이버 블로그와 카페에는 요약 또는 재구성한 글에 "전문 보기" 링크를 붙인다. 같은 글을 그대로 복사하면 구글이 네이버 쪽을 원본으로 판단할 위험이 있다. 반대로 네이버 검색은 자사 블로그와 카페를 우대하므로 네이버 채널을 버려서도 안 된다.

### 4.4 콘텐츠 운영 모델 (한 소스 여러 채널, 주 1회 30분 루틴)

1. 홈페이지에 글을 쓰고 발행한다(원본). 10~20분, 지금 카페에 쓰는 것과 같은 노력이다.
2. 발행 화면의 **'SNS 공유 키트'**에서 채널별 문구를 복사한다. 문구는 자동으로 만들어진다(§8.4).
3. 카페, 블로그, 오픈카톡에 붙여 넣는다(5분). Facebook과 Threads에는 자동으로 공유된다(2단계).
4. 월 1회, 그달의 글 4개를 숏츠 대본으로 바꿔 한 번에 촬영한다(3단계).

→ 변호사가 바꿔야 할 행동은 **"카페에 먼저 쓰던 습관"을 "홈페이지에 먼저 쓰는 습관"으로 바꾸는 것 하나뿐이다.**

**변호사용 분류 규칙(한 문장):** "6개월 뒤에도 유효한 글인가?" 아니면 **이민법 소식**, 그렇다면 **전문가 칼럼**.

**카페 질문을 칼럼으로 만드는 흐름:** 카페에서 답한 좋은 질문을 익명으로 재구성해 'Q&A 해설' 칼럼으로 확장한다. 커뮤니티 질문이 곧 검색용 콘텐츠가 된다.

### 5.2 URL 설계 원칙

- **고정 페이지는 영문 슬러그를 쓴다** (`/practice/green-card`). jkpark처럼 한글 URL이 퍼센트 인코딩되면 카톡이나 SNS에 공유할 때 링크가 길고 지저분해진다.
- **게시글은 번호형으로 한다** (`/news/1234`). 변호사가 주소를 고민할 필요가 없다.
- 한국어가 기본이며 주소에 언어 표시를 붙이지 않는다. 영문은 `/en/` 아래에 둔다.
- 네이버 카페·블로그와 SNS에서 거는 링크에는 UTM을 붙여 어느 채널에서 왔는지 측정한다.

## 6. 업무분야 구성: 의뢰인 질문에 대한 답

### 6.1 세 가지 방안과 권장안 비교

| 방안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| ① 상세 정보를 모두 게재 | 전문성과 SEO에 강함 | 초기 작성 부담이 크다. 법이 바뀌면 낡은 정보가 '오인 광고' 리스크가 된다. 방문자가 길을 잃는다 | △ |
| ② 필요 최소한만 | 빠르고 관리가 쉽다 | 검색 노출이 약하고 전문성이 전달되지 않는다. 상담할 동기도 약해진다 | ✕ |
| ③ 게시판 글로 계속 작성 | 기존 습관과 맞고 계속 업데이트된다 | 구조가 없어 글이 묻힌다. 처음 온 사람이 무엇을 하는 사무소인지 알기 어렵다 | △ |
| **④ 하이브리드 (권장)** | 고정 '허브 페이지'로 구조를 잡고, 게시판 글로 깊이를 자동으로 쌓는다 | 초기 4페이지 원고가 필요하다. 제작사가 초안을 쓰고 변호사가 검수하는 방식으로 해결한다 | ◎ |

### 6.2 권장안의 작동 방식

```
[업무분야 허브: 이민비자·영주권]   ← 고정 페이지 (연 2~4회 점검)
 ├ 개요 / 이런 분께 해당합니다
 ├ 세부 유형 (가족 · 취업 · NIW · 간호사 · 투자 · 웨이버)
 ├ 진행 절차(단계 도식) / 대표 준비 서류
 ├ 자주 묻는 질문 3~5개
 ├ ▼ 관련 이민법 소식 (자동)    ← 글을 쓸 때 '업무분야'를 체크하기만 하면
 ├ ▼ 관련 칼럼·승인 사례 (자동)  ← 여기에 자동으로 쌓인다
 └ 상담 신청
```

- 수수료나 처리 기간처럼 자주 바뀌는 수치는 **USCIS와 국무부 공식 페이지 링크로 대신한다.** 정보가 낡는 것을 막는다.
- **결과:** 변호사가 주 2개씩 쓰면 1년 뒤 각 업무분야 페이지에 관련 글 수십 개가 붙은 '살아 있는 페이지'가 된다. 추가 작업은 필요 없다.

### 6.4 허브 페이지 템플릿 (분량 1,500~3,000자)

### 7.4 이민법 소식 (/news)

- **목록**
  - 맨 위에 '이달의 영주권 문호' 카드를 고정한다.
  - 필터 탭: 전체 | 영주권 문호 | 정책·규정 | 법원 판결 | 기관 공지. 업무분야 드롭다운과 검색을 함께 둔다.
  - 각 행: **날짜(크게)**, 유형 배지, 제목, 요약 2줄, 업무분야 태그. 썸네일은 필수가 아니어서 작성 부담이 적다.
  - 번호형 페이지 이동으로 카페처럼 익숙하게 한다.
- **상세**
  1. 경로 표시(브레드크럼), 유형 배지, 제목
  2. 작성일, **최종 업데이트일**, 작성자(변호사 사진과 이름)
  3. **3줄 요약 박스**
  4. 본문(이미지, 표, 영상)
  5. 공식 출처 링크
  6. 면책 박스(자동 삽입)
  7. 공유 바(카카오톡, Facebook, Threads, 링크 복사)
  8. 상담 안내 박스("이 변화가 내 케이스에 어떤 영향이 있는지 궁금하다면 → 상담 신청")
  9. 같은 업무분야의 관련 글 3개, 이전 글과 다음 글
  10. 작성 후 12개월이 지나면 상단에 안내 배너를 자동 표시(§8.6)

### 8.2 글쓰기 흐름 (카페와 같은 감각)

1. 대시보드에서 **[✍ 이민법 소식 쓰기] [✍ 전문가 칼럼 쓰기] [📅 이달의 영주권 문호] [📥 상담 문의 확인]** 버튼을 누른다.
2. 제목과 본문을 쓴다. 카페에서 복사해 붙여 넣으면 서식을 정리해 주고, 사진은 끌어다 놓는다.
3. 오른쪽 체크리스트를 채운다: 글 유형 ✔ 업무분야 ✔ 3줄 요약 ✔ 대표 이미지(선택).
4. [발행]하거나 [예약]한다. 발행 직후 **SNS 공유 키트**가 열린다.

- 계정 권한: 변호사의 평소 계정은 '편집자'로 둬서 실수로 사이트를 망가뜨리지 않게 한다. 비상용 관리자 계정은 따로 둔다.
- 스마트폰 WordPress 앱으로도 작성하고 사진을 올릴 수 있다.

### 8.3 글 템플릿 (미리 만든 블록 패턴)

| 템플릿 | 구성 |
|---|---|
| **이달의 영주권 문호** | 제목 자동("YYYY년 M월 영주권 문호") / 가족이민(F1·F2A·F2B·F3·F4)과 취업이민(EB-1~EB-5)의 Final Action Date·Dates for Filing 표(빈칸만 채우면 됨) / 지난달 대비 변동 ▲▼ / USCIS가 이번 달 쓰는 표 / 변호사 코멘트 3줄 / 출처(국무부 Visa Bulletin, USCIS) |

### 8.4 SNS 공유 키트 (발행 후 자동 표시)

글의 제목, 3줄 요약, 업무분야, URL을 조합해 채널별 문구를 자동으로 만든다. 각 문구에 [복사] 버튼이 있다.

- **카카오톡·오픈채팅:** `[이민법 소식] {제목}` / `{3줄 요약}` / `👉 {링크}`
- **Threads·Facebook:** `{첫 문장}` + `{3줄 요약}` + `자세히: {링크}` + `#미국이민 #이민법 #{업무분야}`
- **네이버 블로그·카페:** 대표 이미지, 요약, 핵심 포인트, "홈페이지에서 전문 보기" 링크를 담은 HTML(붙여 넣기용)
- **Instagram 카드뉴스:** 제목 1장, 요약 3장, 상담 안내 1장의 문구 세트. Canva 템플릿과 함께 쓴다.
- **숏츠 대본 초안:** 질문으로 시작(5초) → 핵심 3가지(40초) → "자세한 내용은 프로필 링크에서"(10초)
- 링크에는 채널별 UTM을 자동으로 붙인다.

### 8.5 상담 문의 처리 흐름

```
폼 제출 → ① 관리자 화면에 저장
        → ② 변호사·직원에게 이메일 알림 (제목에 분야 표시: [영주권] 홍길동님 상담 신청)
        → ③ 신청자에게 자동 회신 (접수 확인 · 응답 예정 시간 · 상담 전 준비 서류)
        → ④ GA4 전환 이벤트 기록
        → ⑤ 보관 기간(예: 12개월)이 지나면 자동 삭제
```

- 알림 메일이 스팸함에 빠지지 않도록 SMTP 인증과 트랜잭션 메일 서비스를 쓰고, 도메인에 SPF와 DKIM을 설정한다.

### 8.6 오래된 글 자동 안내

작성 후 12개월이 지난 글 상단에 자동으로 안내를 표시한다. 예: "이 글은 2026년 11월 기준입니다. 이후 규정이 바뀌었을 수 있으니 최신 정보는 상담으로 확인하세요."
변호사가 업데이트하면 '최종 업데이트일'이 바뀌고 안내가 사라진다. 이민법 콘텐츠의 노후화 리스크와 오인 광고 우려를 함께 줄인다.

## 9. 기술 아키텍처

### 9.1 플랫폼 비교와 결정

| 기준(가중치) | WordPress 직접 설치형 | SaaS 빌더 (Wix·Squarespace·아임웹) | 헤드리스 (Next.js + CMS) | 한국형 게시판 (그누보드·라이믹스) |
|---|:---:|:---:|:---:|:---:|
| 의뢰인 직접 운영 편의 (25%) | 4 | 5 | 3 | 4 |
| 데이터·도메인 이전성 (25%) | **5** | 1 | 3 | 3 |
| SEO·다국어 (20%) | 5 | 3 | 5 | 2 |
| 초기·운영 비용 (15%) | 4 | 4 | 2 | 4 |
| 보안·유지보수 부담 (15%) | 3 | 5 | 5 | 2 |
| **가중 점수** | **4.30** | 3.45 | 3.55 | 3.05 |

(5점 만점, 제작사 판단 기준의 정성 평가)

- **결정: WordPress 직접 설치형.** 의뢰인 질문 2(이전성)에 대한 결정적 답이다. 세계에서 가장 널리 쓰는 표준이라 어느 업체나 이어받을 수 있다. 경쟁 사이트 4곳 중 3곳도 WordPress다.
- **SaaS 빌더를 배제한 이유:** 디자인과 사이트를 통째로 옮길 수 없다. 의뢰인의 이전성 질문과 정면으로 충돌한다.
- **헤드리스를 배제한 이유:** 이 규모에는 과하다. 업체를 바꿀 때 개발자가 필요하고 운영 비용이 늘어난다.
- **구현 방식 변경(v1.1):** 처음에는 가벼운 커스텀 테마를 권장했다. 제작사가 월정액으로 계속 관리하는 것을 전제로 **Elementor Pro 기반 리치 구성**으로 바꾼다. 벤치마크 사이트 수준의 연출(영상 히어로, 슬라이더, 스크롤 애니메이션, 비자 진단 퀴즈)을 쓴다.
- **바꿔도 지키는 것:** ① 게시글(소식·칼럼)은 기본 블록 에디터로 써서 의뢰인의 핵심 자산을 빌더와 분리한다(§9.3). ② 성능 예산을 운영해 검색 성과를 지킨다(§9.4).

| 카카오 | Kakao JavaScript SDK(공유), 오픈채팅 링크 | 한국형 공유 |
| 이메일 (선택) | 도메인 메일(Google Workspace 등), 예: vincent@도메인 | 신뢰도와 도달률 |

> **원칙: 화려하게 만들되 느려지지 않게.** 리치 구성은 제작사가 계속 관리한다는 전제에서만 성립한다. 관리 품질의 기준은 속도와 보안이다. 모바일 PageSpeed와 Core Web Vitals를 매달 리포트에 넣고, 기준을 벗어나면 그달 안에 고친다. 사이트가 느려져 검색 성과가 떨어지면 재계약이 흔들린다. 의뢰인이 준 참고 사이트들(구버전 방치, 무거운 슬라이더)이 반면교사다.

### 9.3 이전성 설계 원칙 (의뢰인 질문 2에 대한 기술적 답)

1. **도메인과 DNS는 의뢰인 계정에 둔다**(Cloudflare, Namecheap 등). 제작사는 위임받은 관리자다.
2. **표준 형식으로 보관한다.** WordPress 파일, DB 덤프, 업로드 폴더, WXR(WordPress 표준 내보내기 파일)이면 어느 호스팅이나 업체에서든 복원할 수 있다.
3. **콘텐츠 구조(분류 체계 등)는 테마가 아니라 사이트 전용 플러그인에 둔다.** 테마를 바꿔도 글 분류가 사라지지 않는다.
4. **게시글은 기본 블록 에디터로, 디자인 페이지는 Elementor로 나눈다.** 의뢰인의 핵심 자산인 소식·칼럼 글은 빌더 없이도 그대로 남는다. 홈·소개·업무분야처럼 디자인이 중요한 페이지와 게시글 화면의 틀은 Elementor로 만든다. Elementor는 가장 널리 쓰이는 빌더라 다른 WordPress 업체도 이어받을 수 있다. 단 Elementor Pro 같은 유료 플러그인을 제작사 라이선스로 쓰는 경우, 해지 후에는 의뢰인 명의 라이선스가 필요하다는 점을 계약서에 적는다(§11.1).
5. **외부 계정은 모두 의뢰인 명의로 만든다.** Google(Analytics, Search Console, 비즈니스 프로필), 네이버 서치어드바이저, Kakao Developers, Meta. 제작사는 관리자로 추가된다.
6. **인수인계 문서를 둔다.** 구조, 계정 목록, 설정 문서. 비밀번호는 공유 비밀번호 관리자 금고에 보관한다.
7. **301 리다이렉트 목록을 관리한다.** 주소가 바뀌어도 검색 순위를 지킨다.

### 9.4 보안, 성능, 백업, 접근성

- **백업:** 매일 자동 백업(외부 저장, 30일 보관), 업데이트 전 스냅샷.
- **업데이트:** 코어 마이너 버전은 자동 업데이트. 플러그인과 테마는 월 1회 스테이징에서 검증한 뒤 적용.
- **계정 보안:** 관리자 2단계 인증, 로그인 시도 제한, XML-RPC 차단, 최소 권한 원칙.
- **방화벽과 감시:** Cloudflare 방화벽과 봇 차단, 가동 모니터링(사이트가 내려가면 알림).
- **성능 목표(모바일):** LCP 2.5초 미만, CLS 0.1 미만, INP 200ms 미만. 리치 구성에서 이 목표를 지키는 장치는 다음과 같다.
  - 페이지 캐시, CSS·JS 최적화, 스크립트 지연 실행(WP Rocket 등)
  - 페이지별로 쓰지 않는 플러그인 스크립트 끄기(Perfmatters)
  - 히어로 영상은 포스터 이미지를 먼저 보여 주고, 짧고 가볍게 인코딩한다
  - 슬라이더는 첫 장면만 즉시 불러오고 나머지는 지연 로딩
  - 이미지 WebP·AVIF, 한글 폰트 서브셋, Cloudflare CDN
  - Elementor 자체 성능 옵션 활성화
- **접근성:** WCAG 2.2 AA. axe·Lighthouse 자동 점검과 키보드·스크린리더 수동 점검. 영상에는 자막을 단다(접근성, SEO, 무음 시청에 모두 유리).

### 9.5 개발 환경과 저장소 구조

- **로컬 개발:** LocalWP(macOS용 GUI 도구) 권장. 현재 개발 머신에는 Node.js가 설치돼 있지 않으므로 Node가 필요 없는 도구가 간편하다. Docker 기반의 DDEV도 대안이다.
- **버전 관리:** Git으로는 차일드 테마, 사이트 플러그인, Elementor 템플릿·사이트 키트(JSON 내보내기)를 관리한다. WordPress 코어, 업로드 파일, 비밀 정보는 제외한다.
- **배포:** 스테이징을 거쳐 프로덕션에 배포한다. 호스팅사 Git 연동이나 GitHub Actions(SSH·rsync)를 쓴다. 콘텐츠(DB와 업로드 파일)는 프로덕션이 원본이다.

├─ design/                    시안, 디자인 에셋, Elementor 템플릿·키트 내보내기(JSON)

├─ .github/workflows/         (선택) 배포 자동화
└─ .gitignore                 코어·업로드·비밀 정보 제외

### 11.4 해지와 이관 절차 (계약서에 명시)

1. **약정 기간 중 해지:** 미회수 구축비 잔액만 정산한다(산식을 공개). 예: 구축 원가를 12개월로 나눈 금액 × 남은 개월 수.
2. **약정 후:** 월 단위로 자동 연장된다. 30일 전에 서면이나 이메일로 알리면 위약금 없이 해지된다.
3. **이관 패키지:** 해지 통보 후 7영업일 안에 전체 백업을 넘긴다. 파일, DB 덤프, 업로드 폴더, WXR 내보내기, 플러그인 목록, 설정 문서가 포함된다.
4. **권한 정리:** 도메인·DNS와 Google·네이버·Meta 계정에서 제작사 권한을 해제한다(원래 의뢰인 소유이므로 '반환'할 것은 없다).
5. **이전 지원:** 새 호스팅이나 업체로 옮기도록 DNS 전환 안내와 1회 기술 지원을 제공한다.
6. **데이터 삭제:** 제작사 서버의 데이터를 삭제하고 확인해 준다. 상담 문의 기록 같은 개인정보도 포함된다.

### 11.5 월 유지보수 범위 (예시)

- **포함:** 호스팅·SSL·CDN, 매일 백업(30일 보관), 보안 모니터링, 코어·플러그인 업데이트(스테이징 검증), 가동 모니터링, 소규모 수정(월 [N]시간), 기술 SEO 점검, 월간 리포트, 게시 관련 문의 지원.
- **불포함(옵션):** 원고 작성과 번역, SNS 운영 대행, 카드뉴스·숏츠 제작, 유료 광고 운영, 대규모 개편과 신규 기능, 사진 촬영.

## 12. 법규와 컴플라이언스 체크리스트

> 제작사는 법률 자문을 하지 않는다. 최종 문구는 **변호사 본인이 검토하고 승인한다.** 다만 이 목록을 먼저 제시하는 것 자체가 전문성의 증거가 된다.

## 13. 디자인 방향과 시안 계획

### 13.1 디자인 원칙

1. **사람이 먼저:** 실제 인물과 실제 사무실 사진을 쓴다. 법봉, 저울, 자유의 여신상 같은 스톡 사진은 쓰지 않는다.
2. **날짜가 보인다:** 최신성을 시각적으로 증명한다. 날짜 배지와 '이달의 영주권 문호'.
3. **읽기 쉬운 글:** 본문 17px 이상, 행간 1.7, 명도 대비 4.5:1 이상. 40~60대 독자를 배려한다.
4. **움직임은 화려하게, 메시지는 하나씩:** 영상 히어로, 슬라이더, 스크롤 애니메이션을 쓰되 장면마다 메시지는 하나만 둔다. 영상은 무음 자동재생과 일시정지 버튼을 갖추고, 기기에서 '동작 줄이기'를 켠 사용자에게는 애니메이션을 끈다(접근성).
5. **엄지손가락 거리:** 모바일 하단 상담 버튼, 터치 영역 44px 이상.

### 13.2 시안 두 가지

### 13.3 사진 촬영 가이드 (전문 촬영 권장, 반나절)

1. **히어로용 가로 컷:** 사무실 창가나 책상, 자연광. 텍스트를 놓을 여백이 있는 구도.
2. **프로필 세로 컷:** 상반신 정면과 3/4 측면.
3. **상담 장면:** 의뢰인은 뒷모습이나 손만 나오게 연출해 초상권 문제를 피한다.
4. **집필 장면:** 노트북으로 칼럼을 쓰는 모습. "직접 쓰는 변호사"라는 메시지를 시각화한다.
5. **사무실 외관, 로비, 윌셔 거리:** 위치에 대한 신뢰.
6. **방송 출연 스틸:** 사용 허락을 확인한다.
7. **영상 촬영:** 히어로용 시네마틱 영상(사무실, 윌셔 거리, 집필·상담 장면 10~20초)과 숏츠 촬영 세팅을 같은 날 함께 찍는다.

의상은 두 벌 정도 준비하고 시안 색상과 어울리게 맞춘다.

### 13.4 시안 제출물

- 메인 페이지 A안과 B안(데스크톱과 모바일)
- 이민법 소식 상세 1종(읽는 경험을 보여 준다)
- **실제 데이터로 채운다:** 카페의 최신 글 제목, 실제 연락처, 카페에 있는 사무실 사진(시안에 써도 되는지 허락을 구한다). 실제처럼 보일수록 결정이 빨라진다.
- 형식: 반응형 HTML 시안(링크로 전달). Figma도 가능.
- **제작 완료:** `design/mockup/`. 표지 `index.html`에서 A·B안의 메인 화면과 게시글 상세 화면을 볼 수 있다(구성과 확인할 점은 `design/mockup/README.md`).
