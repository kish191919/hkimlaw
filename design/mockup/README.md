# 홈페이지 디자인 시안 (반응형 HTML)

김형걸 이민법 변호사(Law Offices of Vincent Kim) 홈페이지 시안 두 가지입니다. A는 정보 중심, B는 변호사 1인 브랜드 중심으로 구성부터 다릅니다. 변호사님이 의뢰 메일에서 요청한 메뉴 6개(홈·변호사 소개·업무분야·이민법소식·전문가칼럼·상담안내)를 모두 실제 페이지로 만들었고, 영문 페이지와 관리자 글쓰기 화면도 들어 있습니다. 기획 근거는 [docs/website-plan.md](../../docs/website-plan.md), 참고 사이트 분석은 [docs/benchmark-sites.md](../../docs/benchmark-sites.md), B안의 근거인 jkparklaw.com·kfreemanlawoffice.com 상세 분석은 [docs/benchmark-jkpark-kfreeman.md](../../docs/benchmark-jkpark-kfreeman.md)에 있습니다.

## 보는 방법

- `index.html`을 브라우저로 열면 두 시안을 비교하는 표지가 나옵니다. 시안 미리보기, 페이지 목록, 글쓰기 화면은 모두 새 창으로 열려서 표지를 둔 채 두 시안을 오가며 볼 수 있습니다.
- 글꼴(Pretendard, Noto Serif KR)과 지도는 인터넷에서 불러옵니다. 오프라인에서는 기본 글꼴로 보입니다.
- 의뢰인에게 링크로 보내려면 이 폴더를 그대로 웹 서버에 올리면 됩니다(`_build/`는 빼도 됩니다). 모든 페이지에 `noindex`가 들어 있어 검색엔진에 노출되지 않습니다.

## 페이지 다시 만들기

A 홈(`a/index.html`)을 뺀 나머지 23페이지(A 서브 11개, B 홈 + 서브 11개)는 생성기로 만듭니다. 헤더·푸터·빠른 상담 버튼이 모든 페이지에서 같게 유지됩니다. B 전용 화면은 `build.py`의 ‘시안 B 전용’ 구역(`page_home_b`, `about_b`, `practice_b`, `header_b`, `footer_b` 등)에 있습니다.

```
python3 design/mockup/_build/build.py
```

- 글 목록, 업무분야 원고, 상황별 안내는 `_build/content.py`에 있습니다. 글을 추가하거나 분류를 바꾸려면 여기만 고치고 다시 실행합니다.
- 칼럼 표지(`COVERS`)와 방송 출연 영상(`KBS`)도 `content.py`에 있습니다. 실행하면 `assets/covers.js`가 함께 만들어집니다. 시연판에서 변호사님이 글쓰기 화면으로 사진을 올린 글은 그 사진이 먼저 쓰입니다.
- 방송 영상은 포스터를 누르면 그 자리에서 유튜브(youtube-nocookie)로 재생됩니다. 유튜브는 `file://`로 연 페이지에서 재생을 막으므로, 로컬에서는 `python3 -m http.server`(design/mockup 폴더에서)로 열어 확인하세요. 파일로 열면 유튜브 새 창이 열립니다.
- 페이지 구조는 `_build/build.py`에 있습니다. 생성된 HTML을 직접 고치면 다음 실행 때 덮어써집니다.
- Python 3.9 이상, 외부 패키지 없음.

## 시연판: 변호사님이 직접 쓰는 글 (Supabase)

- 글쓰기: 시안 사이트 맨 아래 '변호사 로그인'(https://vk-proposal-a.vercel.app/write, B는 `vk-proposal-b`)에서 로그인하면 이민법 소식·전문가 칼럼에 글을 발행·임시 저장·예약·수정·삭제할 수 있습니다. 사진은 브라우저에서 1600px WebP로 줄여 올립니다. 표지의 https://vk-proposal.vercel.app/write 도 그대로 동작합니다.
- 글쓰기로 들어가는 길: 한 번 로그인하면 그 브라우저에서는 로그인 상태가 유지되고, 시안 사이트 모든 화면 왼쪽 아래(휴대폰은 하단 상담 바 위)에 글쓰기 버튼이 뜹니다. 게시판에서는 그 게시판이 골라진 채로(`/write?board=news`), 글 화면에서는 '이 글 고치기'(`/write?id=번호`)로 열립니다. 로그인 정보는 사이트 주소마다 따로 저장되므로 A와 B, 표지는 각각 로그인해야 합니다(실제 사이트는 주소가 하나라 한 번이면 됩니다). 버튼은 로그인 정보가 남아 있는지만 보고 띄우며, 실제 권한은 글쓰기 화면과 데이터베이스가 확인합니다.
- 발행한 글은 게시판, 홈의 최신 소식·칼럼, 상단 소식 띠, 업무분야 페이지 '관련 글', 게시글 상세(`/post?id=번호`)에 바로 나타납니다(`assets/live.js`).
- 데이터베이스: Supabase 프로젝트 `vk-proposal-demo` (ref `inkaxcxdgrsluikccsln`, us-west-1, kish1919 조직). 설계는 `_build/supabase/schema.sql`, 기존 글 53편은 `_build/seed.py` → `_build/supabase/seed.sql`.
- 권한: 누구나 발행된 글만 읽기. 쓰기·고치기·지우기·사진 올리기는 `editors` 표에 등록된 계정만(행 수준 보안). `assets/config.js`의 키는 공개용(anon) 키입니다.
- 시연 계정 2개(변호사님용 `vincent`, 제작사용 `agency`)는 저장소에 넣지 않았습니다. 비밀번호는 Supabase 대시보드 Authentication에서 바꿀 수 있습니다.
- 비용: 이 프로젝트가 켜져 있는 동안 Supabase 사용료가 붙습니다. 시연이 끝나면 대시보드에서 프로젝트를 일시 정지(Pause)하거나 삭제하세요. 그러면 사이트는 자동으로 정적 시안 내용으로 돌아갑니다.

## Vercel 배포 (발표용 사이트 3개)

| 주소 | 내용 |
|---|---|
| https://vk-proposal.vercel.app | 표지(두 시안 비교) · `/write` 글쓰기 화면 |
| https://vk-proposal-a.vercel.app | 시안 A (첫 화면이 홈) · `/write` 글쓰기 화면 |
| https://vk-proposal-b.vercel.app | 시안 B · `/write` 글쓰기 화면 |

배포용 폴더는 `_build/export.py`가 `dist/` 아래에 따로 만듭니다(원본은 그대로). 발표용으로 '시안' 배지, 시안 메모, '상세 화면 예시' 표시를 숨기고, 주소에서 `.html`을 빼며, 모든 응답에 `X-Robots-Tag: noindex` 헤더를 붙입니다. '확인 필요' 표시와 푸터의 '디자인 시안' 한 줄은 남깁니다. 글쓰기 화면은 시안 사이트마다 같은 주소 안(`/write`)에 넣어, 푸터 '변호사 로그인'으로 로그인한 뒤 그 사이트에서 글쓰기 버튼이 보이게 합니다. 표지의 '글쓰기 화면 보기'는 시안 A의 `/write`로 갑니다.

시안을 고친 뒤 다시 올리기:

```
python3 design/mockup/_build/build.py      # 서브 페이지를 고쳤다면
python3 design/mockup/_build/export.py
D=$(mktemp -d) && cp -R design/mockup/dist/. "$D"/
for d in vk-proposal-a vk-proposal-b vk-proposal; do npx vercel@latest deploy --prod --yes --cwd "$D/$d"; done
```

- **반드시 git 저장소 밖에서 배포하세요(위의 임시 폴더 복사).** 저장소 안에서 `--yes`로 배포하면 Vercel CLI가 프로젝트를 GitHub 저장소에 자동으로 연결합니다. 그러면 `master`에 push할 때마다 저장소 전체(기획서·회신 초안 포함)가 이 주소에 배포됩니다. 2026-11-20에 실제로 이 문제가 생겨 연결을 끊었습니다. 프로젝트 설정의 Git Repository가 `Not connected`인지 확인하세요.
- `dist/`와 각 폴더의 `.vercel/`(프로젝트 연결 정보)은 git에 올리지 않습니다(`.gitignore`). `.vercel/`이 없으면 같은 이름의 프로젝트에 다시 연결하거나 새로 만듭니다.
- Vercel 무료 주소는 링크를 아는 사람 누구나 볼 수 있습니다. 검색엔진에는 노출되지 않습니다.

## 실제 구축(Next.js + Supabase)으로 옮길 때

기획서 v1.2부터 WordPress 대신 자체 개발로 갑니다(기획서 §9). 시연판이 이미 같은 구조라서 데이터베이스와 권한은 그대로 쓰고 화면만 옮깁니다.

- **데이터베이스·권한:** `_build/supabase/schema.sql`(글·편집자·사진 저장소, 행 수준 보안)을 운영 저장소의 첫 마이그레이션으로 씁니다. 업무분야 분류는 `posts.hubs`·`posts.tags` 그대로입니다.
- **페이지:** 생성기(`_build/build.py`)의 페이지 함수 하나가 Next.js 페이지 하나가 됩니다(`page_about` → `app/about/page.tsx` 등). 헤더·푸터·빠른 상담·비자 진단 창은 공통 레이아웃 컴포넌트로 옮깁니다.
- **게시판·게시글:** 지금은 `live.js`가 브라우저에서 글을 불러와 채웁니다. 실제 사이트에서는 서버가 완성된 HTML을 내보내야 구글·네이버 수집과 카카오톡 미리보기가 글 내용을 읽습니다. `live.js`의 채우기 함수(`fillBoards`, `fillHubs`, `renderPost` 등)가 서버 컴포넌트가 되고, 주소는 `/news/번호`, `/column/번호`로 바꿉니다.
- **색·글꼴:** `a/style.css`, `b/style.css` 맨 위 `:root` 변수를 그대로 가져갑니다. `assets/base.css`, `assets/pages.css`도 거의 그대로 씁니다. `assets/mobile.css`는 반드시 가장 마지막에 불러옵니다(휴대폰 덮어쓰기). 시안별로 다른 휴대폰 규칙은 `html[data-theme="a"|"b"]`로 나눠 두었습니다.
- **인터랙션:** 비자 진단, 경로 타임라인, 스카이라인 모션, 슬라이드는 `assets/mockup.js`의 해당 블록을 클라이언트 컴포넌트로 옮깁니다.
- **글쓰기 화면:** `write.html`·`assets/admin.js`를 `/write` 페이지로 옮깁니다. 편집기는 브라우저 기본 기능(`execCommand`) 대신 유지보수되는 오픈소스 편집기(Tiptap 등)로 바꾸고, 저장 형식(정리된 HTML)은 그대로 둡니다.
- **글쓰기 버튼:** `assets/editbar.js`와 같은 동작을 공통 레이아웃에 넣습니다. 실제 사이트에서는 로그인 정보를 쿠키로 두고 서버에서 편집자인지 확인한 뒤 버튼을 그립니다.
